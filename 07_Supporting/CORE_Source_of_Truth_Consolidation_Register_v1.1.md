# CORE™ Source of Truth Consolidation & Reconciliation Register v1.1

## 1. Purpose

This document is the operational reconciliation layer for the CORE knowledge base.

Its purpose is to identify:

- which document governs a subject;
- which documents are supporting modules;
- which documents are implementation specifications;
- which documents are historical / superseded;
- which documents require reconciliation;
- which documents still need to be created.

This document does **not** rewrite the underlying strategy or methodology.

Where two documents conflict, the conflict is recorded here and resolved only through an explicit update to the appropriate authoritative document.

# 15. GOVERNANCE RULE

A document is not authoritative because it is newer, longer or more detailed.

Authority comes from its role in this hierarchy.

The rule is:

> **Master architecture governs → domain module elaborates → implementation specification builds → register records → execution asset expresses.**

When a contradiction is found:

> **Identify → classify → reconcile explicitly → update the authority → preserve historical traceability.**

Do not silently rewrite source truth.
