# CORE Personality Backbone Architecture
## Version 2.0

This document captures the complete personality stack established for the CORE document architecture.

These are **backbone personalities**, not people to imitate literally. Each contributes a specific discipline to a particular document or system.

Two levels must be distinguished:

1. **Explicitly established personalities** in the underlying CORE source work.
2. **Personality stacks agreed during the recent design discussions**, which may not yet be written explicitly into every current MD file.

This distinction matters because we should not retroactively pretend a personality was part of a document when it was not.

# 4. The Core Spine

These personalities are not equal.

The deepest CORE spine is:

> **Seth Godin → Roger Martin → David Bland → Senior Strategy Partner**

with the other personalities acting as specialized engines around that spine.

That means:

### Seth Godin

Provides the **worldview**.

### Roger Martin

Provides the **strategic logic**.

### David Bland

Provides the **testing discipline**.

### Senior Strategy Partner

Provides the **executive synthesis and organisational translation**.

The remaining personalities provide specialist capabilities where needed.

---

# 5. Practical Rule for the Documents

The personalities should be treated as:

> **disciplines to extract, not personalities to imitate.**

For example:

- We do not try to “sound like Hormozi.”
- We use Hormozi for offer clarity.
- We do not try to “write like Perell.”
- We use Perell for body-of-work thinking.
- We do not try to “be Carnegie.”
- We use Carnegie for genuine interest.
- We do not turn CORE into “Roger Martin strategy.”
- We use Martin's strategic logic inside the CORE worldview.

The final product should always sound like **CORE**, not like a collage of borrowed personalities.

---

# 6. Source Discipline

The personality architecture should be maintained with two labels in future documents:

### Explicit backbone

A personality actually specified as part of the document or source architecture.

### Applied discipline

A personality introduced during later design discussions because their method is useful for that document.

This distinction prevents the system from accumulating artificial authority through retroactive attribution.

---

# 7. Master Principle

> **Borrow disciplines, not identities.**

The purpose of the personality architecture is to ensure that every CORE document is built with the appropriate level of:

> **worldview + strategy + diagnosis + experimentation + persuasion + narrative + relationship + network + public intellectual rigor**

while retaining a single coherent CORE voice.
